# Real-Time School Monitoring System — Professional Edition

Real-time school attendance, QR tracking, parent communication, smart alerts and PWA notifications.

## Backend

1. Copy `backend/.env.example` to `backend/.env`.
2. Fill `MONGO_URI`, `JWT_SECRET` and VAPID keys.
3. Run `npm ci` inside `backend`.
4. Run `npm start`.

The server exposes `/health` and `/ready`.

## Security

- JWT authentication with role-based authorization.
- Tenant isolation through `tenantId`.
- Public registration creates parents; the first administrator can bootstrap the installation.
- Web Push subscriptions are bound to the authenticated user.
- Authentication endpoints are rate-limited.
- Secrets are never committed; rotate any credentials that were previously exposed.

## Roles

- `super_admin`: cross-tenant administrative control.
- `admin`: school administration.
- `teacher`: staff/read access where supported.
- `parent`: access only to their children.

## Core flow

`Student -> Attendance -> Smart Alerts -> Notifications -> Parent`

Presence changes are centralized in `backend/services/attendanceService.js`, so REST, Socket.IO and QR use the same business logic.

## Frontend

The existing frontend remains compatible with the existing REST endpoints and Socket.IO events. The AR/FR/EN translation system, RTL/LTR behavior, PWA and parent dashboard are preserved.


## Super Admin

The project now includes a dedicated `/super-admin/` control center. Only users with
`role: super_admin` can access its API or interface.

Features:
- System overview and health
- Multi-tenant institution management
- Cross-tenant user management
- Admin/teacher/parent account creation
- Role management (Super Admin cannot be demoted from the UI)
- Recent activity aggregation
- Arabic/French/English and RTL/LTR support

Create the first Super Admin securely from the deployment shell/database rather than
public registration. Public registration never exposes the `super_admin` role.

## Public Admin/Staff Registration

Public registration supports:
- `parent`: normal registration on the default institution.
- `admin`: registration requires an institution registration code generated by a Super Admin.

Super Admins generate/rotate codes from **Super Admin → Institutions → key icon**. The backend stores only a SHA-256 hash of the code; the plaintext code is shown once when generated.

`super_admin` can never be created through the public registration endpoint.
